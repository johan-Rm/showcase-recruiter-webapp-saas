# requirements

**Ce que le projet a reçu**, par opposition à ce que l'équipe a écrit.

Ces documents ne se maintiennent pas : ils sont datés par nature. Un brief dit ce qui a été demandé
au départ, pas ce qui est vrai aujourd'hui — quand la décision évolue, c'est le cadrage ou la doc qui
bouge, jamais la source. On cite un fichier d'ici, on ne le corrige pas.

| Dossier | Contenu |
| --- | --- |
| [`brief/`](./brief/) | Le brief initial et les questionnaires de récolte d'information |
| [`inspirations/`](./inspirations/) | Références visuelles et produits apportées par le client |

## Où va le reste

- Ce que l'équipe **écrit** à partir d'ici — parcours, règles métier, arbitrages — vit dans
  [`dev-book/cadrage/`](../dev-book/cadrage/).
- Les **maquettes** vivent dans [`ui-ux-design/`](../ui-ux-design/).
- La **charte de marque** et le design system vivent dans
  [`docs/showcase-recruiter-webapp-saas/content/4.design/`](../docs/showcase-recruiter-webapp-saas/content/4.design/).
